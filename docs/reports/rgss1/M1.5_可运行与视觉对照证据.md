# RGSS1 M1.5 — 可运行性与视觉对照证据
> 注：本文写于 2026-10-27 仓库重构前；文中 `backup/` `unpacked/` `build/` `test/` `third_party/` 等路径现位于 `local/` 下，`src/rgss_*.c` 现为 `src/runtimes/rgss2/*.c`，`tools/` 已按流水线分桶（unpack/pe/analysis/probe/verify）。


日期：2026-10-26 ｜ 对象：`unpacked/RGSS1_103J_fix.dll`（重建版）vs `backup/RGSS103J.dll`（原版带壳）

## 方法

- 测试游戏：`test/RGSS1_m11_run/`（m11 副本，Game.ini 指向 RGSS103J.dll）
- 截图：`PrintWindow(hwnd, PW_RENDERFULLCONTENT)`——让窗口自身渲染到 DC，免受遮挡/焦点影响
- 输入：`AttachThreadInput + SetForegroundWindow + keybd_event`（绕过 Win11 焦点抢占拦截，实测 foreground_ok=True）
  - 注：`PostMessage(WM_KEYDOWN)` 无效（RGSS1 输入走 GetAsyncKeyState 轮询）；`SetForegroundWindow` 单独调用无效（被系统拒绝）
- 对照：同一脚本、同一时序（启动→9s 标题→ENTER→5s→截图），原版/重建各跑一次

## 结果

## 结论

1. 重建 DLL 在真实游戏上 **启动→标题→进入关卡→Tilemap/精灵/窗口皮肤渲染** 全链路与原版**逐像素一致**。
2. 标题画面的唯一差异是游戏自身的动画帧（已用同 DLL 连拍对照证明），非重建缺陷。
3. 四个 apphelp 污染槽的修复桩（`fix_visible/fix_tick3/fix_tick5/fix_unknown`）在标题与关卡路径中**零调用**——其语义仍待 M2 运行期定名；不影响当前验证路径。
4. 先前一次"黑屏 + 猫精灵 + ×1"画面 = 窗口未获焦点时的 PrintWindow 抓取结果（原版同样如此），非缺陷。

## 1. 三版本壳鉴定（PE 静态）

| 文件 | 节布局 | 壳 | 结论 |
|------|--------|-----|------|
| RGSS102J.dll | `.text/.rdata/.data/.rsrc/.reloc/.aspack/.adata`（7 节） | **ASPack**（.aspack 实锤） | 全部节缺 EXECUTE 位（0xC0000040）→ **DEP 开启的 Win11 上无法运行**（本机实测 LoadLibrary 报错 1114；补 X 位副本可跑） |
| RGSS103J.dll | `CODE / DATA / .rsrc`（3 节，节名带尾空格） | **UPX 系**（CODE RS=0、DATA 含 stub、stub 为 NRV2 解压 + E8E9 修正） | 文件内无 "UPX!" 标记，`upx -d` 不可行；走通用 OEP 冻结脱壳 |
| RGSS104E.dll | 8 节、节名被抹空 + `.rsrc/.xpdata/.adata` | **ASPack 变体**（stub 为 `call OEP; ret 0xC` 包装式） | v1（LoadLibrary 后）dump 正常 |

## 3. OEP 定位

- **103J = RVA 0xC1214**：UPX 型 stub 尾部 `popa; … jmp 0xC1214`（非 ATTACH 分支也跳同一目标），DR0 实测命中。
- **102J = RVA 0xC0DEA**：stub 尾部 `ret 0xC; push 0x100C0DEA; ret`，imm 运行期写入（文件态为 0），从冻结 dump 读出。
- **104E = 未定**：交接为 `call eax`（RVA 0x1CF088），因 objdump 线性反汇编在壳头数据块失步，需 IDA 级递归反汇编（M1.5 或 M2 补）。v1 dump 已够 diff，不阻塞。

## 4. 关键坑与结论

1. **apphelp 全局钩子**（Win11）：103J 有 4 个导入槽被 GetProcAddress 层钩到 apphelp 蹦床
   （RVA 0x367E0 / 0xE730C / 0xE73A4 / 0xE73C8）。改名、改哈希均逃不脱 → 非 SDB 按名/按哈希匹配，
   是 Win11 对该组 API 的进程级包装。VX 202E 的 2 槽（MessageBoxW/IsWindowVisible）同属此机制。
   102J 零污染 = 其老 ASPack stub 手工走导出表解析，绕开了 GetProcAddress 钩子。
   **M1 处理**：四槽接 RGSS1_probe.dll 探针（参数/返回地址留痕），**M2 运行期定名**。
2. **103J 导入表被 UPX 销毁**：原版 IMAGE_IMPORT_DESCRIPTOR/OFT 不在内存。改用 iatmap 指针扫描
   （同 boot modmaps 逐槽定名）：**263 个导入、26 组描述符**。主 IAT 簇 0xE7000..0xE744C（266 槽），
   8 个零散小簇（延迟/分离表）+ 壳自己的 loader 表 0x19C0B0（排除）。
3. **dump 头节属性被 UPX stub 复位**：CODE 被剥写位（0x60000080），直接照抄会让 loader 写 IAT 时 AV
   （smoke 第一版在 0x100E7000 崩溃）→ mkpe 补 0x80000000 写位。
4. 24 个"落在模块区间但非导出地址"的 dword = 假阳性常量，已排除（字节保留原样）。

## 6. 三版本互 diff 摘要（M1 级，函数级 M2）

- 导入集：102J=262、103J=263；差集均为 CRT/运行库演化
  （103J 独有 GetConsole*/WriteConsole*/GetProcessHeap/IsValidCodePage/GetGlyphOutlineW…；
  102J 独有 Fls*/IsBad*Ptr/GetSystemInfo/GetFontData…），**无任何 RTP/注册表/行为类异常项**。
- **《103J 第三方改动清单》初版：未发现第三方功能补丁** —— 103J 疑为官方 1.03 代码 + UPX 重打包壳。
  终裁留 M2：与 102J/104E 逐函数比对 + 与官方 Ruby 1.8.1 源码 diff。
- OEP 均落在 0xC0000~0xC2000（CRT 区），图像大小 102J=0x17F000 / 103J=0x19D000 / 104E=0x1F8000。

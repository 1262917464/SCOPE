# ADR-0002 — 运行时与版本的目录粒度判据

日期：2026-10-27（重构工单 Q15r/Q29 的决策落档）　状态：已采纳

## 背景

`local/backup/` 显示运行时与版本是两个轴：RGSS1 有 102J/103J/104E 三个版本、RGSS2 有
200E/200J/202E/202J 四个、RGSS3 有 300/300_/301 三个，RM2K 是 2000/2003/2003Steam 三个 EXE。
重构前 `src/` 的粒度两者混用（`RGSS202E.def` 按版本、`rm2k/` 按运行时）。

## 决策

1. **不设全局规则，每个运行时自决**（Q15r）。主人否决了"同运行时各版本逐字节可 diff"的
   全局假设——RGSS300 与 RGSS301 疑似差距很大，实测前不能预设共享。
2. **缺省形态**：`src/runtimes/<线>/` 单树 + 版本参数（如 rgss2 的 `VERSION=202E`，
   影响导出表与微差）。
3. **拆版本子目录的门槛**：只有当该运行时的第二个版本**实际开始重建**、且实测差异证明
   无法用条件编译共享时，才拆 `src/runtimes/<线>/<版本>/` 并列（rgss3 已按此预留形态：
   现有源码位于 `rgss3/300/`）。拆分决策须在本 ADR 补充记录实测差异证据。
4. **rm2k 暂不分 2000/2003**（Q29=C）：LCF 数据层确认共享，引擎层差异未测。等真正做
   2003 时再决定用版本参数还是拆目录；若拆且 lcf 无需改动，届时上提 `src/shared/` 零成本。
5. **`src/shared/` 准入**：只有第二个运行时实际需要同一份代码时才创建目录。
   已知首个候选：`src/runtimes/rgss2/ext/Win32API.c`（绑定 Ruby 1.8.1 + mingw 的
   stdcall 修补，与 RGSS 版本无关，见 `docs/analysis/common/win32api_cdecl.md`）。

## 后果

- 结构诚实：树里没有"预测的抽象"，重复代码可见且可 diff。
- 代价：跨线重复（Win32API、未来的 Bitmap 等）在共享证据出现前保持复制状态。
- 修订本 ADR 须附实测证据（差异表 / 对拍结果），不接受"感觉差不多"。

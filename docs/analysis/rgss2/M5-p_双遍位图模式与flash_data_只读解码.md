# M5-p Tilemap 双遍位图模式 与 flash_data 闪烁 —— 只读解码

> 状态：只读研究，零代码改动。
> 证据源：full_disasm.txt（0x10017000/0x10017250/0x10017970/0x10016bc0/0x1000f540/0x1000f610）、
> 脱壳镜像虚表读取（0x1010527c）、System.rvdata passages 实测、Scripts.rvdata 全文检索。

## 1. 双遍位图模式（内部双子渲染器）

### 1.1 对象结构（0x10017000 / 0x10017250）

C++ Tilemap 外层对象（vtable 0x10104df4，≥0x10074 字节）构造时 malloc 两个 0xCC 字节
内层子渲染器：

| 外层偏移 | 子对象 | 构造实参（0x10017250 的 a2） | 语义 |
|---|---|---|---|
| +0x04 | obj0 | 0 | **普通遍**：画 layer 0–2 全部"非 ☆"图块 |
| +0x08 | obj1 | 1 | **☆ 遍**：只画 layer 2 中 passages bit 0x10 置位的图块 |
| +0x0C | （= obj1 同指针别名） | | |

0x10017250 把 `+0xC4 = 外层 this`、`+0xC8 = a2(模式号)`，并再分配一个 0x2A0 字节
工作区（0x100989d0）与一个 `a2×0xC8` 字节数组（0x10098c80）。
内层对象 vtable 0x1010527c：slot[0]=0x100178f0（析构），**slot[9]=0x10017970（逐层绘制）**，
slot[2]=0x10098960（标脏刷新，0x10016bc0 对两个子对象各调一次）。

外层其余字段（ctor 初始化）：+0x10..+0x30 = 9 个位图槽（TileA1..A5,B..E）、
+0x10034 = map_data 指针、+0x10038/3C/40 = W/H/Z、+0x10044 = flash_data 指针、
+0x10048/4C/50 = flash W/H/Z、+0x10054 = passages 指针、+0x10058 = passages 元素数、
+0x1005C..+0x1006C = ox/oy/可见区缓存、+0x10070 = 动画计数器。

### 1.2 门控逻辑（0x10017970 内，0x10017a44/0x10017ac5）

```
mode = [esi+0xC8]                 ; 0=普通遍, 1=☆遍
flag = (passages[tile_id] & 0x10) != 0    ; WORD 表, 越界按 0
mode==1 且 layer<2      → 整格跳过（☆遍只画 layer 2）
mode==0 且 flag==1      → 跳过
mode==1 且 flag==0      → 跳过
其余                    → 绘制（0x10017340）
```

即：**passages bit 0x10 = VX 图块管理器的 ☆（"显示在最上层"）标记**。
实测 System.rvdata passages（9288 项）：空块 id 0 = 0x10，另有 59 个真实图块
（0x55/0x68/0x1E2/0x200-0x225 等全部 <0x800 的 B–E/A5 块）置位；
自动块（≥0x800）无一置位（编辑器不允许给自动块打 ☆）。

效果：☆ 图块被从普通遍中剥离，由 obj1 单独一遍绘制（仅限 layer 2），
从而能以独立 z 序盖在角色精灵之上——这就是"双遍位图模式"的全部内容。

### 1.3 每帧驱动

`Tilemap#update`(0x1000f1f0) → 0x10016d50（动画计数器 +0x10070 +1）→
0x10016bc0（外层刷新）：按 ox/oy 计算可见图块区间写 +0x10068/+0x1006C，
然后对 obj0/obj1 各调虚表 slot[2] 标脏。实际绘制走虚表 slot[9]，
由每帧渲染遍历调用（间接调用，本报告未逐指令追遍历器）。
注册/注销链表 = 0x1017B538（外层注册；析构 0x10016F00 释放两个子对象并摘链）。

### 1.4 对重建版的含义（未改动）

重建版单遍顺序画 layer 0/1、无 ☆ 剥离。本测试游戏：
- ☆ 图块存在（59 个），但若只摆在 layer 0/1（☆ 遍不画）则原版**不显示**，
  重建会显示——潜在可见差异；
- 若 ☆ 块只在 layer 2：原版在角色之后补画，重建在角色之前画——z 序差异。
当前对拍地图无 ☆ 块（passages 置位块未被使用），对拍不受影响。
**渲染顺序（2026-10-29 运行期实测订正）**：Frida 钩 0x10017970（遍绘制）与
0x10014ae0（精灵面绘制），帧内序列 = mode0 → mode1 → 精灵，三者共用同一
返回地址 0x10098fc4 —— 派发器在 0x10098fb5（`mov edx,[esi]; mov edx,[edx+0x24];
call edx`，对同一 z 有序成员指针数组逐个调 slot9；同 z 按注册序，obj0 先于 obj1
先于后建精灵）。即 ☆ 遍仍在精灵**之前**，与此前"盖于角色之上"的推测相反。

## 2. flash_data 闪烁

### 2.1 数据通路

- Ruby 设定器 `Tilemap#flash_data=`(0x1000F610)：与 `map_data=`(0x1000F540) 同构——
  校验 Table 类后，把 Table C++ 字段拷入外层：
  **Table C++ 布局：+0x0C=x, +0x10=y, +0x14=z, +0x1C=数据指针**
  → flash 指针存 +0x10044，W/H/Z 存 +0x10048/4C/50（map_data 对应 +0x10034/38/3C/40）。
- flash Table 与 map 同布局，每格 **WORD（带符号 16 位）**。

### 2.2 逐格闪烁绘制（0x10017BEA–0x10017CDE，位于 3 层图块循环之后、每格执行）

```
if ([外层+0x10044] == 0) 跳过                     ; 未设 flash_data
f = (int16)flash_data[W*y + x]
if (f <= 0) 跳过
; 颜色包三个 4 位通道:
A = ((f >> 5) & 0x78) / 8   → 即 bits 8–11 的值 kA（×8 后截同掩码）
B = ((f >> 1) & 0x78) / 8   → 即 bits 4–7
C = (f & 0xF) * 32 / 8      → bits 0–3
; 闪烁振幅: 三角波
k = (动画计数器 >> 2) & 7        ; 0..7，每 4 帧一步，32 帧一周期
if k >= 4: k = 8 - k            ; 4,5,6,7,8,7,6,5（先 +4 使用，见下）
k += 4                           ; 最终 4..8
三个通道各乘 k / 8；基准三通道 = 128,128,128（WORD×3）
以 32×32 目标矩形（当前格）调用 0x10096920（带色填充/混合原语，模式字 2）
```

语义：**每格可独立着色的加色闪烁**，32 帧周期三角波呼吸（与水面动画共用计数器，
相位 = 计数器>>2）。f 的三个 4 位字段 ≈ R/G/B 强度（各 0–15），
通道基准 128 + 振幅调制。参数结构（0x40–0x55 区的 WORD 排布）已解到语义级，
逐字节排布未核对——该路径在本游戏为死代码（见 2.3），核对性价比低。

### 2.3 本游戏实况

Scripts.rvdata 全文检索 `flash_data`：**零命中** —— 游戏脚本从不设置 flash_data，
外层 +0x10044 恒为 0，整个 0x10017BEA 块不执行。重建版无需实装即可与本游戏对拍一致；
若未来目标工程用到（事件脚本直接调 tilemap.flash_data=），按 §2.2 补。

另勘误：M5-o 报告 §7.2 曾把 0x10017920 称为"角部暗块"——该判定维持
（左邻+左上均为 0x1100–0x1FFF 墙时的 16×16 补块）；flash 走的是另一个原语
0x10096920，两者不同函数，此前报告未混淆但特此注明。

## 3. 结论一览

| 机制 | 引擎位置 | 本游戏是否触发 | 重建现状 |
|---|---|---|---|
| 双遍位图模式 | 外层 +0x04/+0x08 双子渲染器，passages bit 0x10 门控 | ☆ 块存在但当前地图未用 | 未实装（对拍不受影响；实装方案见 §1.4） |
| flash_data | +0x10044 表 + 0x10096920 逐格填色 | 死代码（脚本零引用） | 未实装（无需） |

## 4. 实装记录（2026-10-29）

§2.2 遗留的"参数排布残余"已全部收口（0x10096920 → 设备虚表 0x101404b4 slot+0x40
→ 0x100a3d00 → 0x100a3c10 MMX 核 → 0x10095c20 视口裁剪）：

- 色对象（栈上构建）：`{mode=2, alpha=0, mul=128×4(B,G,R,A), add=(c3,c2,c1,0)}`，
  mode&3=2 选核；mul/add 为 WORD×4 通道向量（BGRA 序）。
- 混合：先按 ctx 视口裁剪 32×32（0x10095c20，空裁剪不画），再逐像素
  `t = 饱和255(src + k·nib)`，`out = src + (t−src)·F[w] >> 8`；
  **F 指标 = 裁剪后宽度 w**（F[x]=x+1，32 → 33/256 ≈ 12.9% 强度），
  k = ((动画计数器>>2)&7) 三角波 4..8（与水面动画共用相位）。
- 原地作用于合成面（src=dst 同一面）。

实装（graphics_classes.c）：
1. **双遍 ☆**：compose 拆两遍——普通遍（layer 0–2 非☆块，精灵之前）+
   ☆遍（layer 2 的 ☆ 块，精灵/窗口之后）；☆ = passages bit 0x10
   （`tile_star_flag`，空块 id0 视为置位）。阴影条仅在普通遍 layer 0。
   注：普通遍层范围从旧的 0–1 修正为原版的 0–2。
2. **flash_data**：`draw_tile_flash`——f=(int16)flash[W*y+x]>0 时按上式混合；
   flash 表为 W×H 单层（无 z）。
3. 顺序已实测订正：☆ 遍置于精灵之前（紧随普通遍），见 §1.4 运行期实测；
   obj1 对空块的 TileB(0,0) 绘制按不发生处理（pass 2 加 id!=0 守卫）。

对拍（keytest，同图）：墙区 exact **100%**、沙区 95.5%/86.4% 与实装前一致
（无回归）；全屏 near 波动为水面动画相位差（截图时机不同步，非缺陷）。
本游戏 flash_data 为死代码、当前地图无 ☆ 块，两功能处于"按解码待命"状态。

## 三-A、误报排除（已核实不存在，防止复发）
- ~~"原版防盗版联网校验（0x1008EF40）"~~：**误报**，2026-10-28 销案。
  核实：0x1008EF40 = Ruby 1.8.1 `win32.c` 的 `is_socket()`（win32.c:1598）——
  汇编 `call 0x100fc2f0(fd, 0xffff, 0x1008, &sockbuf, &optlen)` 即
  `getsockopt(fd, SOL_SOCKET=0xFFFF, SO_TYPE=0x1008, ...)`，失败时
  `WSAGetLastError()==WSAENOTSOCK(0x2736)/WSANOTINITIALISED(0x276d)` → 返回"非 socket"，
  与源码逐参数一致；TLS/临界区/GetVersionExW 段是 RUBY_CRITICAL 的惰性初始化。
  其调用方 0x1008F060 是 select() 模拟的 fd 分流辅助（fd_set：count + 64 元素数组 = FD_SETSIZE）。
  教训：**二手结论（M5-k §4.2）未经源码对质就入清单**；凡"神秘用途"地址，先查
  local/third_party 的 Ruby 源码再定性——原版内嵌完整 Ruby 1.8.1，大部分"怪函数"是 Ruby 自身。

### B33/B50 blt & stretch_blt 混合语义重写（2026-10-29，review+整修线）

触发：外评"blt/stretch_blt 完全不对"。静态逆向（混合器 0x10096680→traits
表 0x1015e710→0x100a43e0→内循环）定性后，因原版进程内探针不可行（GameMain
崩溃，见 docs/analysis/rgss2/game_exe_调用序列.md），改用 **Game.exe 端到端
黑盒对拍**：gen_blt_rvdata.c 用重建 DLL 进程内 Marshal.dump 生成自测脚本，
原版/重建各跑一次真 Game.exe，密集采样六组（srcA sweep × op sweep × dstA
sweep × 缩放采样 sweep，60+ 数据点）。

钉死的原版语义（原版实测，非推断）：
- ea = (srcA*op + 127)/255 —— 与 LUT 0x1019ca90 逐字节一致
- out_a = ea + da*(255-ea)/255（D 行 6 点全中；159 之谜 = straight-over）
- RGB：da=255 时精确为 dst + sar((src-dst)*(ea+1),8)（= 权重表 0x1018bb90
  [ea]=(ea+1,ea+1,ea+1,0) 的 MMX 循环 0x100a0600）；da=0 时 (src_rgb, ea)
  （即使 ea=0 保留 src RGB）
- 缩放采样 = 32.32 定点累加器、**步长截断** (sw<<32)/dw、pos 从 0 每输出
  像素推进 —— 步长截断使精确命中点取 idx-1（8→6 的 x=3），是 floor(x*sw/dw)
  模型对不上的关键证据，与 0x100a06d0 的 add/adc 循环对应

修复：bm_blt/bm_stretch_blt 重写（blt_compose + 双轴定点累加器）+ TypeError。
验证：对拍 diff 仅剩 D 行 da=32/64 两点 RGB ±2（原版 MMX 16-bit lane 逐通道
截断，四族整数模型均无法复现，实际游戏影响极小）；b19test 回归 ALL PASS。
教训：① 静态 MMX 循环的 psrlw/paddb 组合不可靠手推，黑盒密集采样+数值拟合
才是钉死舍入的唯一途径；② "P2 矛盾"浪费一小时——叠加测例忘记 dst 已被上一
轮 blt 修改，黑盒脚本必须每例用全新 dst；③ 原版进程内 GameMain 不可行时，
Game.exe+注入 rvdata 是可靠的端到端对拍通道。

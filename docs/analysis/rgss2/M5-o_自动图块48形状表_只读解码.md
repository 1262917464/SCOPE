## 2. 地图数据模型（实测确认）

**map_data 的 short 直接存合成 id：`id = 0x800 + kind*48 + shape`，kind=(id−0x800)/48, shape=(id−0x800)%48。**
引擎绘制路径无任何邻接计算——形状由编辑器/存档数据预先烘焙。

实测（Map001）：`0x800` 出现 9676 次（全包围海面）；另见 0x814/0x81c/0x818/0x810/0x808/0x802/0x828 等
（kind 0 的 shape 20/28/24/16/8/2/40……边缘形状），全图 kind ∈ {0, 27, 38}。
普通块 id<0x800（本图 0x601/0x64B/0x667 → A5，idx=(id>>8)+5 计算得 11？——注：0x600–0x7FF 走 idx=4）。

**重建版现有模型 `(id−1)/48` 是错的**：它把 id 2048 映射成 kind42"深海"，
而原版 2048 = kind0 shape0 = A1#0 全包围（水内部）。这就是地图菱形点阵缺陷的根因。

## 3. 三张 48 形状表（核心交付物）

静态数据，磁盘加壳版为全零，运行期由脱壳代码填充；从脱壳镜像抠取：
`T0 @ RVA 0x10104df8`、`T1 @ 0x10104f78`、`T2 @ 0x101050f8`，每形状 8 字节 =
4 个角 × 2 字节 `(qx, qy)`，角序 = 左上、右上、左下、右下（循环 i=0..3，
目标块 = (dx+(i%2)*16, dy+(i/2)*16) 16×16，源块 = (qx*16+Xbase, qy*16+Ybase) 16×16）。

qx,qy 为 16px 单位坐标（T0 的 qy 可达 5，即 64×96 单元格的下半延伸区；
T1 只有 qy 0–3，T2 只有 qy 0–1；未用形状全 0）。

## 4. kind → 位图/基点/表选择（0x10017340 自动块分支逐字转录）

位图数组 `bitmaps[]` 在 C++ Tilemap +0x10010（idx0=A1, 1=A2, 2=A3, 3=A4, 4=A5, 5..10=普通块按 id>>8）。
t = kind>>3。

### A1（kind 0–15，TileA1.png 512×384，bmp idx 0，表 T0/T2）

| kind | Xbase(ebp) | Ybase(esi) | 表 | 动画 |
|---|---|---|---|---|
| 0 | 0 | 0 | T0 | 水平 3 帧乒乓：X += [0,64,128,64][(cnt/30)%4] |
| 1 | 0 | 96 | T0 | 同上 |
| 2 | 192 | 0 | T0 | 无 |
| 3 | 192 | 96 | T0 | 无 |
| 4 | 256 | 0 | T0 | 无 |
| 5 | 448 | 0 | T2 | 垂直 3 帧循环：Y += ((cnt/30)%3)*32 |
| 6 | 256 | 96 | T0 | 无 |
| 7 | 448 | 96 | T2 | 瀑布同上 |
| 8 | 0 | 192 | T0 | 无 |
| 9 | 192 | 192 | T2 | 瀑布 |
| 10 | 0 | 288 | T0 | 无 |
| 11 | 192 | 288 | T2 | 瀑布 |
| 12 | 256 | 192 | T0 | 无 |
| 13 | 448 | 192 | T2 | 瀑布 |
| 14 | 256 | 288 | T0 | 无 |
| 15 | 448 | 288 | T2 | 瀑布 |

公式：k≥4 时 X = ((k&7)>>2)*256 + (k奇 ? 192 : 0)；
Y = (((k&7)>>1)&1 + 2*(t==1))*96；偶→T0，奇→T2+瀑布。

计数器来源：Tilemap#update 每次 +0x10070（即每逻辑帧 +1），
水帧速率 = 30 帧/步（60fps 下 0.5s）。

### A2（kind 16–47，TileA2.png 512×384，bmp idx 1，表 T0）

X = (kind&7)*64；Y = (t−2)*96（t=2..5 → Y=0/96/192/288）；单元格 64×96。
kind&7==7 的四块（kind 23/31/39/47）置 wrap 标志（见 §6）。

### A3（kind 48–79，TileA3.png 512×256，bmp idx 2，表 T1）

X = (kind&7)*64；Y = (t−6)*64（t=6..9 → Y=0/64/128/192）；单元格 64×64。

### A4（kind 80–95，TileA4.png 512×480，bmp idx 3，t=10..11）

X = (kind&7)*64；Y = (5t−50)*16 + (t 奇 ? 16 : 0)（0x10017601 的 neg/sbb 链：
t 偶 → (−16+0x10)=0，t 奇 → 16）→ t=10: Y=0，t=11: Y=96；
t 偶→T0，t 奇→T1。
区带 t=10: 0–96（T0，含 qy=5 阴影延伸），t=11: 96–160（T1，64 高）——不重叠。
（初版解码误写 t=10→16 / t=11→80 并疑区带叠置；2026-10-29 复读汇编修正，
A4 实测对拍墙区 near±8 = 100%。kind 96–127（t=12..13 → Y=160/256…）表内仍有空间，
但本游戏未用。）

## 5. 绘制循环（0x10017694–0x100177ca）

```
for i in 0..3:
    (qx, qy) = table[shape*8 + i*2], table[shape*8 + i*2 + 1]
    # kind&7==7（仅 A2）且 qy==1 时：qx = {0,3,2,1}[qx]（水平镜像）
    src = (qx*16 + Xbase, qy*16 + Ybase)   16×16
    dst = (dx + (i%2)*16, dy + (i/2)*16)   16×16
    blit(bmp, src, dst)                    0x10096680
```
frame 0 的全包围形状实测：TileA1 (16..48,48..80) 为纯水蓝 ✓；
孤立形状 (0..32,0..32) 为沙岸色（A1#0 自带沙缘）✓；瀑布帧区色 ✓。

## 6. kind&7==7 环绕镜像（A2 专用，0x100176ee–0x10017732）

A2 的第 8 列 kind（23/31/39/47）绘制时，凡 qy==1 的角，其 qx 经
`{0→0, 1→3, 2→2, 3→1}` 镜像替换——用水平翻转的第 1 行四分块模拟绕圈海面。
同条件参与两个谓词（0x100171a0/0x10017200）：这类 kind 自身不投影、不接收常规阴影。

## 7. 阴影系统

1. **条状影**（0x100177e0）：当前格为 A2/A3（0xB00–0x10FF）且非 kind&7==7、
   且正上方格满足 0x10017200（是"可投影墙"）时，以上方墙的 shape 查 T0，
   取其**角 2、角 3** 中 qy==5 的四分块（判定条件 `T0[shape].byte[5]==5`，
   即 shape 28–31 系），源 = 16×**8**（`sy = qy*16 + Ybase + 8`，取该 quarter 的下 8px），
   目标 = 当前格顶部 (dx+(i%2)*16, dy) 16×8 —— 即墙体投在下方格上的 8px 阴影。
2. **角部暗块**（0x10017920）：A5 墙（0x610–0x7FF，谓词 0x100171a0）或上述 A2/A3，
   且 (x−1,y) 与 (x−1,y−1) 均为 0x1100–0x1FFF（A3/A4 墙）时，blit 16×16，
   参数观察到 flags 0xe0 / 0x80000000（疑为实心填充/半透明标志，细节待查，
   本图未触发路径）。

## 8. 对重建版的结论（只读，不改代码）

- 重建 `draw_autotile` 的数据模型需整体替换：id 基底 0x800、kind 0–15=A1、
  16–47=A2、48–79=A3、80–95=A4、shape 直接来自 map 词。
- 邻接布尔近似无法复现原版效果：原版 shape 由编辑器烘焙（含 kind&7==7 镜像、
  qy=5 阴影区、A3 的 16 形状/64×64 单元等），必须换用 §3 三表 + §4 几何 + §6 镜像。
- 原注释锚点"id 2048→kind42→A1#10 深海"不成立：2048 = kind0/shape0（海内部）。
- 位图数组 idx：0=A1..3=A4, 4=A5, 5..10=id>>8 普通块（本图 0x6xx→idx 4=A5 分支，
  与 `cmp esi,0x600` 边界一致）。

## 9. 遗留未知

- A4 Y 公式与 TileA4.png 的实际区带对应（§4 ⚠）。
- 0x10017920 的 0xe0/0x80000000 参数语义。
- `bitmaps[8]` 数组容量 8 vs idx 10（0x10016d60 写 i≤8；普通块 idx 可达 10）
  ——高位 idx 是否越界/被截断待运行期确认。

## 11. A4 墙实测补验（2026-10-29）

用户在测试图补画 A4 墙（kind 81=t10 行 96 块、kind 89=t11 行 48 块，shape 含 0）。
首测墙区全错但纹理相似——**根因是白盒转录错误**：0x10017601 的 `neg/sbb` 链被我算反
（正确：t 偶 → 偏移 0；t 奇 → +0x10），Y 写成 16/80，砖纹周期掩盖了 16px 错位。
修正后对拍（keytest，双方同图 md5 be1dcf0f）：

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 墙区 near(±8) | ≈0% | **100%** |
| 全屏 exact | 15.2% | **50.1%** |
| 全屏 near(±8) | 43.5% | **80.8%** |

残余 = 水面动画相位差。教训登记：多步位运算链（neg/sbb/sete）必须逐条推旗标，
不得心算跳步；与用户"不得拍脑门"标准一致——中途一次偏移直方图属于黑盒尝试，
已废弃，最终结论全部出自汇编原文。
